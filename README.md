# hsl26-robot-b-detector

Решение квалификационного задания хакатона StarLine 2026 (HSL26): детекция и
локализация мобильного робота Turtlebot2 ("робот Б") в облаках точек лидара
Livox MID-360, записанных роботом "А" на ROS 2 Humble. Регламент задания
описан в `docs/regulations.md`.

Статус: рабочий прототип. Пайплайн — удаление пола, выделение кандидата
"робот Б" среди прочих объектов сцены, оценка позиции (x, y) — реализован и
проверен живыми прогонами на всех 7 предоставленных записях (static_1m,
rot_0.5m/1m/2m/3m, mov_01/02).

Требования: ROS 2 Humble, Python 3.10+, зависимости `numpy` и `scipy`
(ставятся автоматически при сборке пакета).

Установка:

```
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src
git clone git@github.com:Hrand29/hsl26-robot-b-detector.git
cd ~/ros2_ws
colcon build --symlink-install
source install/setup.bash
```

Данные: bag-файлы (7 записей — static_1m, rot_0.5m/1m/2m/3m, mov_01/02) в
репозиторий не включены из-за размера. Скачать по ссылке из регламента
квалификации HSL26 — https://disk.yandex.ru/d/aaqaNpTZLNcLtg — и распаковать
в папку `data/` внутри клонированного репозитория (каждая запись — отдельная
папка с `metadata.yaml` и `.mcap`).

Запуск: один launch-файл поднимает проигрывание bag-файла, узел-детектор и
RViz разом; закрытие окна RViz останавливает всё сразу.

```
ros2 launch robot_b_detector detector.launch.py \
    bag_path:=<путь-к-папке-с-bag>/rosbag2_..._rot_1m
```

В RViz видно исходное облако точек, облако без пола, подсвеченный кластер
робота Б и красную сферу с текстовой подписью координат `x=.., y=..` над
ним. В терминале, где запущен узел, раз в секунду печатается диагностика:
кто выиграл отбор и с какими показателями прошли остальные кандидаты —
полезно, чтобы понять, почему решение выбрало именно этот объект.

Как это работает: плоскость пола находится RANSAC-ом и переоткалибровывается
раз в несколько секунд (не на каждом кадре — иначе шум в оценке плоскости
визуально "отращивает" пол обратно при накоплении кадров в RViz). Облако без
пола кластеризуется, и среди кластеров ищется основание робота Б — по
диаметру, касанию пола, ограничению по высоте, радиусу через RANSAC-фит
окружности (устойчивее к тому, что сенсор часто видит только часть дуги
основания) и по отношению плотности точек рядом с кандидатом к размеру
самого кластера — этот последний признак отличает слоистую, разреженную
структуру робота от сплошных поверхностей вроде стен и мебели похожего
размера. Позиция публикуется только если у победившего кластера достаточно
точек; на скудных данных (окклюзия во время движения, самая близкая
дистанция) решение честно молчит, а не гадает.

Известные ограничения: на дистанции 0.5 м в комнате есть похожий на робота
объект, который иногда выигрывает отбор; во время движения при выезде
робота за препятствия трекинг позиции прерывается (детектор не
докручивает/не предсказывает положение, просто перестаёт быть уверенным,
пока робот снова не станет виден).
